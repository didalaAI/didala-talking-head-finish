# 口播成片 · 公开版

输入是用户自己的已剪视频和对应SRT。优先保证文意、可读性、实际动作和形式变化；保持原声原速1.0，无BGM。全屏动画与真人段按完整论点安排，避免接点闪回真人。

## 先读什么

- 制作前读 [V4效果选择与品质](references/production.md)，再按[40段机制索引](references/v4-effect-catalog.json)找实际代码。索引中的原案例数量和话题不成为新片默认时间轴。
- 操作脚本先读 [运行与项目格式](references/runtime.md)。`assets/template/src`包含可运行的实体MG、文字进入/收稳和可配置截图推近，不靠形容词重猜风格。
- 需要生成场景时读 [H3与云端接入](references/generation.md)及[镜头配方](references/h3-shot-recipes.json)。模型权重不随Skill分发。
- 在WorkBuddy、豆包工作或其他宿主使用时先读[跨客户端运行边界](references/host-compatibility.md)，确认当前进程确实能访问素材、调用命令和渲染，不把安装成功当成成片成功。

## 制作

1. 检测环境、读取原SRT与视频元信息，查看用户本期的人物、手势和背景。不使用示例人物、声音或字幕替代用户原素材。
2. 逐段说明“这句话里的对象发生了什么变化”，再选真人旁字、穿身、MG、实际截图或H3。先让观众理解现象，再到对应语义给方法；避免全片同款文档卡、黑底PPT或同一机器人改字。
3. 初始化新项目；按本期语义编写`plan.json`和必要的新组件。内置MG是上下文窗口案例的具体实现，新题材需改写其文案/对象/动作。不要只替换标题而保留不匹配的例子。
4. 字体、颜色、字级和阅读停留参考现有实现。人物静图仅用于排版；成片用动态视频。穿身文字必须有本期动态人物mask，缺mask时重新设计成旁字，不能假称已实现穿身。
5. H3只用于适合的具体演绎。设计丰富的空间、道具和镜头，角色/物件确实完成动作，关联镜头用真实尾帧续接。中文宜用后期准确字层，不牺牲动作来修字。缺生成后端时明确说明，不拿静图/冻结填满。
6. 原生动作先内部审核，再做超分/插帧并记录实际规格。镜头可以与真人、不同MG相接；Vox只是其中一种效果，不应用到全片。
7. 运行校验和小样，内部修好后继续整片。字幕与原声完整，声音从原录音和独立SFX混合，防止音效重复叠加。导出后核对当前MP4解码、帧数、声画同步、关键动作与人物进出；技术检查、视觉检查、人工试听分开记录。

默认输出1080p60、同名原SRT、可编辑项目及检查记录。24fps生成素材不能称原生60fps。公开代码与第三方模型各自许可。

封面及发布文案按用户当次范围制作；没有发布授权不上传平台、发消息或修改账号。Skill安装及调用不等于获得云端上传或费用方面的无限授权；生成前让用户了解所选后端与素材去向。

## 可执行入口

```text
python scripts/studio.py doctor
python scripts/studio.py demo --project <空目录>
python scripts/studio.py setup --project <项目目录>
python scripts/studio.py render --project <项目目录>
```

真实视频使用`init --video <视频> --srt <字幕> --project <空目录>`。这会建立`needs_authoring`工程；先完成本期分镜和素材，再标为ready并渲染。不要将初始化成功当成成片完成。初次运行可能需要安装依赖；所有路径由参数/配置提供，不假定某位作者的盘符、用户名或账号。
